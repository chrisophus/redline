# Writing style

Applies to all prose: docs, comments, commit messages, PR descriptions, chat.

Write like an engineer in a design doc: plain words, specific claims, uneven sentence length.

- No em dashes. Use a comma, period, colon, or spaced hyphen.
- Use the word a person would say out loud, not the slightly more precise one. Every unusual word makes the reader stop and translate.
- Don't announce what's coming. No list preambles, no labeling a statement as honest or direct, no restating the question.
- Don't wrap up. No closing aphorism, no summary section, no offer to help further.
- Don't build sentences for rhythm: no "X, not Y" contrasts, no triplets, no mirrored clauses.
- Don't coin a term and then reason from it.
- No filler intensifiers or sentence-starting adverbs.
- No headers or bullets for short answers. No bold inside prose.
- Comments explain what the code doesn't. Commit subjects are imperative and start with the change.

Before finishing, reread for anything the reader would pause on and rewrite the sentence.
